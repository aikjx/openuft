# 卷首

## 一、这本书是什么

《来料审计论：机检方法论与判决总账》是 openuft 项目对一批自称统一四大基本力的外部文稿（本库称「来料」，代号 ROOT V5–V45）所作审计的**叙述性成书**。它不提出新理论，不做新计算，也不汇总「灵感」。它做一件更窄的事：

> 把「这条主张凭什么算一个预言」变成一台机器能判、且判错时能被发现的操作。

书稿正文按「对象 → 方法 → 口径 → 案例 → 定价 → 仪器 → 边界 → 复跑」八章展开，每章末尾给出该章数字的**载体文件名**。全书的聚合数字只有一个载体：本目录 [`精算/_census_report.txt`](../精算/_census_report.txt)（由同目录 `audit_corpus_census.py` 现跑产出，rc=0，二跑 stdout 逐字节同值 6 207 B）。

## 二、为什么写成书而不是继续堆判定册

判定册是按卷追加的：一卷一册，一册一账。这种结构对**审计**是对的（每册自证自己的字节），对**理解**是错的——新人读完 28 份可解析的册子，仍然说不出「这套东西为什么一直没产出预言」。八章本要回答的就是这一句，而它需要的不是更多条目，是把散在闸门、对照、自捕登记里的纪律抽出来，讲成一条可反驳的论证。

同时立一条**反重复纪律**：本书不成为第二个权威源。

| 需要的东西 | 权威载体（不在本书重落） |
|---|---|
| 一条主张的逐条判定 | 该卷判定册 `判定/判定_TUFT-r*.md` |
| 40 条机读判据的名录与口径 | `判据手册_10月新增四十条判据汇编与审查流水线_2026-10-20.md` |
| 九道工序流水线 | `方法全谱_九道工序与全部方法条目清点_2026-10-20.md` |
| 体系级达成度 | `本项目_方法论与成果总览.md` |
| 语料级聚合数 | 本书 `精算/_census_report.txt` 与 `audit_corpus_census.json` |

本书凡是引用上表任一载体的数字，都**点名那个文件**；凡是我在书里看到「4698/8190 = 57.4%」这样的数，它的出处一定写着 `07_统一场方程/94_第54轮…J71….md` 的行号。

## 三、阅读方式

- **只有 20 分钟**：读 `../论文_来料主张的机检审计方法与判决总账.md`（单文件论文版，含全部关键读数表）。
- **想知道我们怎么算的**：第二章（分层与铁律）+ 第三章（口径）+ 第八章（复跑）。
- **想知道结论是什么**：第四章（ROOT V27 九条判决逐条）+ 第七章（关死的与开着的）。
- **想反驳我们**：第八章 §8.3「推翻一条判决需要造什么」，那里把每类判决的反例形状先写明了。

## 四、诚实边界（先于任何结论）

1. **覆盖面由针的形状决定。** 盘上判定面 139 份，本书三把尺取到 28 份，其余 111 份是「模板跨代不同形 ⇒ 未提取」，不是零值、也不是缺陷。（账一现扫，`_census_report.txt`）
2. **高通过率不是好消息也不是坏消息。** 568 条 PASS 绝大多数住在「精确代数／数值复现」两层，含义仅是**来料没有算错**；判决层（G 层）几乎单向转否。把 81% 读成「八成主张成立」是这类台账最常见的误读。
3. **不裁定 ≠ 否证。** 书中每一处 BOUNDARY／O 层都写着「未算」，不写「错」。
4. **时点性。** 本库工作树有并发写入者。本书正文里所有「最新／最大／当前」的字节数与号段读数都是 2026-11-02 时点值，标了「现扫」；引用前必须复检磁盘——同库的盘点册已示范过一次：盘点期间新版本即已落盘。
5. **物理不在射程内。** 本书不裁「空间光速螺旋是不是真实的自然图景」，只裁「这句话此刻是否构成一个可被否证的预言」。
