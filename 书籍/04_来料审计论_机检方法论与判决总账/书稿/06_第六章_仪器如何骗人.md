# 第六章　仪器如何骗人：审计器的失败模式与处置

审计器最容易出错的地方不是被审对象，而是它自己。本库把这些失败叫「仪器自捕」（E 层）：**判据被我们自己的错弄红／弄绿**，而不是来料变红。本章按机制归类，每类给出实例与处置。

## 6.1　七类已实例化的失败模式

**(1) 恒 0／满格读数先当针坏。** 一把尺对一切输入给同一个答案，它测的是自己。处置：任何「全部通过／全部为零」必须先过一发变异体。样例：C02 用 $\beta\sqrt{1-\beta^{2}}$ 逼单调尺响（抓到 2827 处递增）；C10 把 $\sigma_x\sigma_y$ 右端符号写反，得 $\begin{pmatrix}2i&0\\0&-2i\end{pmatrix}$ 非零差——A11 的 9/9 因此是「认符号」的，不是只数对子。

**(2) 比字符串而不是比值。** r351 第一把收口尺拿字面串（「Sigma 64」「E 15」「五槽 0/5」）在三张面之间找同一本账，把「这张面没用这个形状印」读成「三面不同值」⇒ 造出**三条假红**。处置：每张面的数由该面自己的形状正则现取，只比值；缺陷本身写进见证件头部「缺陷自陈」。

**(3) 判集塌缩时「0 命中」＝「无缺陷」。** 扫描集为空时一切 `all(...)` 型判据自动绿。处置：分母断言 + 硬失败。样例：C07 要求正对照 5/5 **且**扫面集 $\ge 20$ 份（实测 40 份），否则本卷一切「净增量／老账」裁定作废；普查脚本在路径缺失时直接 `return 2`，不印 0、不印空表。

**(4) 期望值假设了环境。** Windows 下管道到的子进程 stdout 是 CRLF，README 是纯 LF、判定册是 CRLF。样例：`_out` 的层表扫描一开始取到空，因为行尾有 `\r`；判定册小节正则一开始取不到，同因。处置：统一 `replace("\r\n","\n")` 后再做行锚正则，并断言面非空。

**(5) 负对照打在尺不检查的属性上。** 改了下游会钳住的字段，变异体成为空操作，「有牙」被假证明。处置：负对照必须攻击**被判的那个属性**；若那个属性在盘上没有可攻击面（如 r351 的 N10：磁盘侧字节数无法用改 README 打破），就单独加一发内存覆盖来证明该格有牙。

**(6) 手打的计数与漂移的面。** 登记条里手写「`_out` 15 槽」，而那张表实测 **14** 个键。处置：登记条**不印**这类计数，计数只住在会自己印它的载体上；同时在台账里把这次手打错误本身披露出来（比追加一条 E 更便宜，且不移动判定册的自指字节与 README 的分层分母）。

**(7) 号段与坐标凭记忆派生。** 曾有执行计划拟「写入 ROOT V39」并「主攻分支 C（Einstein–Cartan 扭转主丛）」。核盘：`*ROOTV3[3-9]*` 只命中 V34；`扭转主丛` 全仓 **0 命中**；EC 挠率方向已被 r341/r295/r355 覆盖。⇒ 两条坐标都不成立（`整理_攻破态势盘点…` §一 D1/D2/D3）。教训固化：**开册坐标一律先查磁盘**，盘点 ≠ 攻破。

## 6.2　本章的新实例：普查抓到一份登记自己不平的册

语料普查对 F2 家族的 24 份面做头条闭合核对（PASS+FAIL+BOUNDARY+INFO 是否等于自报条目数）：

- 23 份成立；
- **1 份破坏**：`判定_TUFT-r332_nullFrenet标架重写_伪参量化重建曲率挠率与光子层承载物_2026-11-01.md` 行 4 自报「条目 22」，四类之和 **21**（差 1）。

普查把这个差**逐名点出**，不做四舍五入、不并入合计悄悄抹平（`_census_report.txt` 账一节 ★行）。这是审计器对台账自己开着的样子。

## 6.3　三面收口：让结论被第三只眼复核

一卷的关键数字在三张面各写一遍，句式不同：

```
README 登记行（人读的那两句）
   ↕ 只比数值
源码/_out_rNNN.txt（引擎 stdout，含层表与闸门行）
   ↕ 只比数值
判定/判定_TUFT-rNNN….md（§〇 层表 / §二 主册 / §九 闸门名册）
```

r351 的收口件（只新增、不覆盖；落盘前后各印一行正本／README／判定册字节以自证未动账）打印：跨面格 **22/22** 同值、**1** 发正对照 + **10** 发单点负对照全响、两遍运行 stdout 逐字节同值。

本书把同一思路推到语料级：`audit_corpus_census.py` 的控制组里除了 F2/F1 两把尺各自的合成面正／负对照，还加了两条对 r351 的**跨载体互认**：

| 检查 | 内容 | 实测（现印） |
|---|---|---|
| X1 | 面 §〇 合计 == stdout 条目数 | 64 == 64 |
| X2 | 面 §二 A/B/G/C 行数 == stdout「判决类」 | 44 == 44 |
| X3 | 面 §二 判决类带变异体 == stdout「带变异体」 | 44 == 44（另 2 行 INFO 类也填了该列，属口径宽一档，已注明） |
| X4 | 面 §二 行数 == §〇 合计（行数不靠手打） | 64 == 64 |

X3 的括号很重要：**若两处定义不同，必须说出来哪个宽**，否则「同值」是巧合。这条纪律来自一次真实失灵——两把尺的口径不同（一把普查含 `.test.js`、一把棘轮不含），删 3 处却读数 10→10。

## 6.4　「崩溃不等于红」：退出码的三种语义

- `rc=0` 且对照全绿 ⇒ 该卷/该普查的数可引用；
- `rc=1` ⇒ 有判决为红（红是有内容的结果）；
- `rc=2` ⇒ **输入面缺失或对照未全绿 ⇒ 不产生任何判决**，此时任何「0 缺陷」都不成立。普查脚本的对照失败路径正是 `return 2`。

## 6.5　本普查自己欠的债（先于结论披露）

- **F3 家族（3 份面，条目 Σ 55）没有独立变异体。** F1/F2 两把尺各配了合成面正／负对照（改数⇒读数变、破覆盖列⇒计数降），F3 只有闭合核对。⇒ 引用「F3 子集 55 条」时，它的强度弱于 F1/F2；加尺与加变异体必须同批交付（第八章 §8.4 第 2 条把这条写成了对读者的要求，也对本脚本生效）。
- **F2 的守卫与控制组是各卷自报的满格**，本普查只核对了「相等」，没有独立复算各卷闸门。⇒「控制组满格 24/24」的含义是**登记如此**，不是「已由第三方验过」。
- **未提取的 111 份面里可能藏着更多闭合破坏。** 现有三把尺看不见它们；本书因此不说「全库只有 1 份登记不平」，只说「可解析子集里有 1 份」。
