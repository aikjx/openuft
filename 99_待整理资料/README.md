## 两条硬规则

1. **不做未核验的归属。** 文件名同名不等于同一体系（已知案例：`全域统一场论_*.md`
   文件名带 TUFT，本体却是 S13 的阴阳对偶旋量 + Hopf 六方程闭环）。因此来料一律
   记 `待归属`，只写**线索**，不写结论。
2. **来源来料不提升证据等级。** 材料被搬进来，只表示位置发生了变化；
   它能否作为某个体系的证据，取决于它算过什么、算到哪一步。

## 入库规则

「入库」= 某主题 / 材料从本区移出、归属到具体体系（落点 `01_独立体系/S*/`、`06_统一体系层/` 或 `07_统一场方程/`）。判定与处置：

1. **核验门槛（先算后归）**：必须对该候选体系跑过第一性审查 / 精算（算法联盟引擎、或 `03_跨体系研究` 脚本），给出 PASS / FAIL / BOUNDARY 读数。**禁止「同名即归属」**——文件名带 TUFT 不等于 S14，本体须逐件核对（已知反例：同名 `全域统一场论_*.md` 实为 S13 阴阳对偶旋量 + Hopf 六方程闭环）。
2. **登记义务**：归属后在目标体系 `claims.csv` 登记主张（状态 `verified` / `falsified` / `open`），并在 `system.json` 的 metadata 注明来源线索（链接回本区主题目录）。
3. **目录契约（verify.py 不变量）**：落点文件夹名必须与目标体系 `system.json.directory` **逐字一致**；已核验材料禁止继续堆在 `99_待整理资料/`。
4. **证据等级不提升**：来源来料搬入本区不改变其证据等级；只有「算过 + 登记」才算该体系的证据。
5. **冲突处置**：若来料与某体系已登记 `claims` 冲突（如人工场 ↔ M03），**禁止强行归属**——先在 `11_证伪与反例/` 登记冲突，再决定归档（→ `90_历史归档/`）或保留为开放问题（留本区）。
6. **封存 vs 入库**：已完成位置迁移、待逐件归属的既有来源 → 落 `90_历史归档/`；只有关联到具体体系的材料才叫「入库」。
7. **主题毕业**：当某主题已有 ≥1 个体系材料按上述 1–3 完成归属，该主题目录可保留为「问题索引」（仅留本文件中的一句话定义与线索），具体材料移至目标体系。
