## 结论先行

**已对接上中台**，且对接较为完整：登录、用户 / 部门 / 角色三类数据同步均已实现，并落地到本系统的 `sys_user / sys_dept / sys_role` 表。模块位于 `ymkj‑service/ymkj‑sso/sso‑fszsj`（`fszsj` = 佛山政数局）。

但存在一处**数据完整性缺口**：登录调用 `/user/current` 接口**不返回 org/dept 相关字段**，部门、权限无法在登录时由中台实时下发；系统采用**默认部门 \+ 默认角色**兜底策略。

## 一、是否对接上中台：登录 \+ 信息同步

### 1\. 登录对接（已实现）

- `FszsjSsoProvider` 实现框架 `SsoProvider` SPI，`providerId="fszsj"`，拦截路径 `/fszsj/**`、`/rpa/matter/**`。

- 中台地址：`https://zwzt.foshan.gov.cn`，OAuth2 授权码模式（开启 PKCE）。

- 两套登录入口：

    - **前端跳转式**：`GET /fszsj/sso/loginUrl` 获取授权页 URL → 用户政务中台登录 → 中台 callback 回调带回`code` → 后端兑换 token、获取用户信息、新建 / 更新本地用户、签发本地 token、写入`localStorage`。

    - **后端接口式**：`POST /fszsj/sso/login`（传入`code`），返回业务系统`token` \+ 中台`accessToken`。

### 2\. 用户信息同步到本系统（已实现）

- 登录阶段执行 `FszsjUserSyncService.autoSyncOnLogin`：根据`userName`查询本地用户，不存在则新建（`userName/realName/phone/email/sex`）；已存在则增量更新姓名、电话、邮箱。

- `LoginUser` 使用本系统自有 token 体系签发，后续请求走本地鉴权，**不会重复调用中台接口**。

- 中台`accessToken`存入`sys_auth`表，`type=FSZSJ_SSO`，基于 userId 做幂等更新。

- 中台返回用户字段：`id,userName,realName,status,phone,email,idCard,gender,avatar,createTime`（源码 `FszsjSsoService.getCurrentUserInfo`）。

### 3\. 部门同步（已实现，但登录场景缺失部门信息）

- 中台主动推送回调接口：`POST /fszsj/sso/dept/sync`；携带`timestamp/nonce/signature`完成验签，根据`operType=INSERT/UPDATE/DELETE`维护`sys_dept`表。

- **关键缺口**：`FszsjSsoProvider.mapUserInfo`代码中定义了`deptId/deptName/orgCode/orgName`映射逻辑，但中台`/user/current`实际响应报文**没有该组字段**；代码注释明确标注 “政数局登录用户信息接口不含 org 字段”。

    - 登录新建用户时无法拿到真实部门，统一归属配置项`defaultDeptId`，默认值`100`，对应配置类`FszsjSsoConfig.defaultDeptId`，在`autoSyncOnLogin`逻辑生效。

    - 真实部门层级数据只能依赖中台调用`dept/sync`推送落库；同步逻辑**以部门名称做去重匹配，未使用中台 deptId 映射**，层级依靠`parentId`还原。

### 4\. 权限（角色）同步（已实现）

- 中台主动推送接口：`POST /fszsj/sso/role/sync`，由`FszsjRoleSyncService.syncRole`处理。

- 本地角色`roleKey`统一增加`fszsj_`前缀；中台外部 ID 存入`remark="FSZSJ:<id>"`，数据权限`dataScope=2`（自定义）。

- **登录兜底授权**：`autoSyncOnLogin`内部调用`ensureDefaultRoleForUser`，自动分配默认角色`fszsj_user`（政数局用户，数据权限仅本人），保障登录后可正常使用系统。

## 二、对接全部业务流程

|流程|方向|接口 / 方法|代码落地|
|---|---|---|---|
|单点登录（授权码兑换 token）|本系统→中台|`/oauth/token`|`exchangeCodeForToken`|
|获取当前用户信息|本系统→中台|`/user/current`|`getCurrentUserInfo`|
|校验 token 有效性|本系统→中台|`/oauth/check_token`|`validateToken`|
|client\_credentials 模式获取应用 token|本系统→中台|`/oauth/token`|`getAccessToken`|
|token 刷新|本系统→中台|`/oauth/token`|`refreshToken`|
|部门数据同步|中台→本系统（推送）|`POST /fszsj/sso/dept/sync`|`FszsjDeptSyncService`|
|用户数据同步|中台→本系统（推送）|`POST /fszsj/sso/user/sync`|`FszsjUserSyncService.syncUser`|
|角色数据同步|中台→本系统（推送）|`POST /fszsj/sso/role/sync`|`FszsjRoleSyncService`|
|登录态用户创建 / 更新 \+ 默认角色分配|系统内部|`autoSyncOnLogin`|写入`sys_user/sys_auth/sys_role`|
|初始化上报（业务存量数据供中台拉取）|中台主动拉取本系统|`GET /fszsj/sso/dept/init`、`/user/init`|返回业务 Bean 列表|
|登出通知回调|中台→本系统|`/notice/logout`，已配置`logoutUrl`|仅配置地址，接收端点未实现|

对接逻辑符合文档 3\.3 节业务系统定位三点要求：①初始化上报；②双向数据同步；③单点登录。

**数据同步健壮性实现**

- 验签：`FszsjSyncService.verifySignature`，SHA‑256\(`timestamp+nonce+appSecret`\) 签名校验；时间戳 5 分钟窗口，nonce 通过 Redis 防重放攻击。

- 幂等控制：Redis 键 `fszsj:sync:idempotent:*`，24 小时内相同 ID \+ 相同 operType 不再重复执行业务处理。

## 三、主动登录 vs 被动登录处理逻辑

文档第四章区分显性 / 隐性登录，结合代码实现分为 4 类场景：

### 1\. 主动登录（用户主动发起，业务系统作为 SP）

- **场景**：用户访问业务系统未登录，系统跳转政务中台完成登录。

- **处理链路**

    1. 前端调用`GET /fszsj/sso/loginUrl`跳转中台授权页面；

    2. 用户中台登录完成，携带`code`回调业务系统；

    3. `exchangeCodeForToken`兑换 token → `getCurrentUserInfo`拉取用户信息 → `autoSyncOnLogin`新建 / 更新本地用户、分配默认角色 → 签发业务系统本地 token。

- 当前**唯一完整可用登录链路**。

### 2\. 被动登录 / 信任传递（中台已登录，跳转进入业务系统）

- **场景**：用户已经在政务中台登录，点击业务系统入口，中台携带 ticket/code 直接跳转业务系统，实现一处登录处处登录。

- **处理逻辑**：服用同一套 callback、code 兑换逻辑；业务系统不区分登录触发来源，合法 code 即可完成兑换、用户同步、签发本地 token。**无独立代码分支**，依靠 code 合法性、签名校验统一鉴权。

- 框架层`SsoAuthenticationFilter`支持对`/fszsj/**`、`/rpa/matter/**`请求，使用请求头`Authorization: AuthCode <code>`直接 API 认证；`FszsjSsoProvider.authenticate`解析该头部完成兑换并写入`SecurityContext`。

### 3\. 隐性登录（业务系统登录页输入账号密码，后台调用中台校验）

- 文档 4\.2\.2 定义该模式：业务系统自有登录页面，后端调用中台用户名密码校验接口。

- **现状：未实现**，模块没有调用中台密码校验端点；当前仅支持授权码回调模式。若政数局要求该能力，属于待补充开发项。

### 4\. 被动数据同步（中台推送用户 / 部门 / 角色）

- “被动” 含义：中台主动调用业务系统同步接口，业务系统接收请求执行业务写库；对应部门、用户、角色三套`/sync`接口。

- 和登录流程相互独立，用于保障两边数据一致性；依靠签名校验 \+ Redis 幂等防重复处理。

## 四、风险点清单

1. **登录流程无法获取中台部门信息**：`/user/current`返回报文缺少 org/dept 字段，登录创建用户固定分配`defaultDeptId=100`；真实部门结构只能依靠中台推送`dept/sync`。同步逻辑按**部门名称匹配，而非中台唯一 ID**，存在部门重名冲突、ID 漂移风险。

2. **全局登出未落地**：配置`logoutUrl=/notice/logout`，但是业务系统没有实现对应的接收接口；中台 “一处登出、处处登出” 广播退出功能不生效。

3. **隐性登录接口缺失**：文档定义的业务系统页面账号密码代校验能力没有实现，如对接要求启用该模式，需要新增开发。

4. **回调地址默认值问题**：`callbackUrl`默认值`http://localhost:8080`；生产环境需要修改为正式域名，支持切换为数据库表`fszsj_sso_config`驱动配置。

5. **两套用户映射机制并存，注意区分**：通用`SsoController`存在`SsoUserMapping`（第三方账号‑本地账号映射，管理员审核绑定），但是`sso‑fszsj`模块**没有复用该组件**，直接通过`userName`写入`sys_user`；两套机制不可混用，避免业务逻辑混淆。
