## 七、线 2：σ 窗口反演（本轮新方法）

对理论值 T 与新读数 O 及其零假设 O0，把误差棒 σ 当作自由量反演：

- 相容所需**下界** `σ_min = ‖T − O‖ / z_crit`；
- 保持可判负所需**上界** `σ_max = ‖T − O0‖ / z_crit`（σ 再大，连 O0 也相容，读数就判不出理论对错）；
- 窗口存在 ⇔ `σ_min < σ_max` ⇔ `‖T − O‖ < ‖T − O0‖`，用精确 Fraction 比较，不拍浮点容差；
- 若 T 与 O 逐位相等（观测副本），χ² 恒为 0 对任意 σ，是**恒等式陷阱**，单列并排除出命中。

理论输出侧两路机读：act = AST 取 `row()` 第二参数数值字面量 15 条，exp = 行首正则 14 条，差 1 条如实登记。候选 120 对；**严口径（单位精确同一）0 对**；宽口径按精确量级 sanity 保留 74 对，仅作反事实压力测试的上界，其中单位严格匹配 0 对 ⇒ 明确不作为独立预言证据。

★**本机核最重的一条**：E7 的读数是**理论侧属性**——它来自第六轮「脚本里的数值是字面量、来源内无推导链」的归属机读，与观测中心值 O 和误差棒 σ 完全无关。对全部 74 对 × 4 个扰动方向（O 乘 2、除 2、加 σ、减 σ）共 **296 次**重算，认证状态恒为假；同一批扰动下 σ 窗口状态却发生变化，证明窗口判据有判别力而认证节点不响应。

## 十、本轮实现事故（真实发生，已修复）

1. **零假设按单位乱配**：见第五节，把中子质量配到 Λ_QCD5；改同对象优先并加守卫显式检查 P09 不得再出现。
2. **预设「宽口径应有相容对」被自己数据推翻**：见第一节，改驱动量为「全部排除」并如实报负读数，未放宽任何守卫。
3. **`add()` 未由 ok 驱动 kind**：初版守卫失败时仍标 PASS，counts 里看不到 FAIL；改为失败即标 FAIL，使 `final_of` 的挡门逻辑可机读。
4. **`N_WINDOW_NONE` 漏算无零假设的配对**：初版只算「有零假设但窗口为空」的 18 对，与守卫 note 的「空或不可定义」口径不符；改为 `总宽口径对数 − 窗口非空数`，读数 42 对，note 与判定表一致。
5. **理论侧单位字段不规范**：全库 `row()` 第四参数出现短横线、空串斜杠 cent、空串等形态，导致严口径 0 对同时含口径不全因素；不追改历史脚本，单列 BOUNDARY。
6. **`add()` 参数含内嵌 ASCII 双引号**：初版守卫 note 里直接写了 `"-"` 等形态，Python 字符串被截断；按中文正文禁 ASCII 双引号的纪律改为中文描述。
7. **★并发会话改 README 使时序型判据误报**：本轮核验期间另一会话持续规范化 README（术语替换与 BOM 增删），使「MD5 前后相等」判据把外部改动记成 `zero_deletion=false` / `readme_unchanged=false`。按第九轮元纪律**不放宽守卫**，改判据驱动量为「机核对 README 无任何写模式调用」的 AST 结构性证明，并把并发改动前后 MD5 如实登记为 BOUNDARY；时序型读数仍保留在核验 JSON 里供追溯。
8. **HTML 巨型三引号与表达式交替反复截断字符串**：改用纯部件文件 + 列表拼接，避免引号边界自伤。
9. **★并发会话把 6 个文件重命名，快照误记为「删除」**：同一会话随后把含旧术语的 6 个文件改名为 ZUFT 口径，使中途一次核验的快照 `deleted` 非空。机读用两种替换规则逐一验证新名文件确实存在，据此把「删除」判据精确化为**重命名 ≠ 删除**，未放宽任何守卫。★该 6 个是本轮运行期间观测到的过程事件，**最终稳定复跑时快照已包含新名文件，故最终核验 JSON 的 `renamed_by_concurrent_session` 为空列表**；过程读数留档于 BOUNDARY 说明，不与最终判据读数相混。

★上述 7、9 两条共同催生一条新的可复用纪律：**当仓库可能被并行会话改动时，「前后 MD5 相等」「文件仍在原路径」都是时序型判据，会把外部改动误报为本册缺陷；应改用「本册机核不存在对该文件的写操作」的结构性判据，并把删除与重命名分离、把并发前后读数一并留档**。三次事故均未通过放宽守卫解决。
