## 二、防编造机制（本册最重要的工程设计）

「跨册指纹表」是**人工编码**的（跨册阅读必须人工判断哪些条目讲的是同一件事）。
为防止「指纹里的 id 是编的」，**每条指纹的每个 id 都必须在对应册 json 的
items / records / checks / verdicts / canon / expel 中实际命中**，否则该条 guard 判 FAIL、
退出码 2。命中方式（`id:` 或 `title~`）与命中册数全部写入产物。

> 实测效果：本机制在首跑即抓出 **6 处问题** —— CORE 册的 X-1/X-4/X-5/X-7 存放在 `expel`
> 列表、元数据册 F2 与 CORE K-f 分属不同列表、可视化册的 F09 只以字典型键存在
> （`k_dimensions`）、以及**摘要声称「prediction_urel 两列全空」与实测不符**。
> 前 5 项已修复；第 6 项转化为本册的新发现（见 §五 D-04）。

## 八、红线

- **本册不做物理判决**，只做跨册层归一与一致性裁定；单式判定一律回链原册，
  同族缺陷**回链不宣称新发现**。
- **指纹的「分组」是人工判断，但每条 id 的存在性由机器强制校验**；本册不把人工判断伪装成机器结论，
  命中方式（`id:` / `title~`）在产物中逐条标明。
- **量纲自洽 ≠ 物理成立**：10-03 册自带反例（式 23 量纲 100% 放行却与日地系统差 8.5e87 倍）。
- **`verified` 2 条与审计判负方向相反**（D-03），本册只记录，不代替人工裁定。
- **有效域**：成立于 2026-10-03 时刻的五份 json + claims.csv；源材料修订后须复跑再判。
