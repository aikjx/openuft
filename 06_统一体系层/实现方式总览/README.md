## 什么是"实现方式"

同一个统一场论主张，可以有多种承载形态。实现方式指**该主张以什么手段被表达、计算、传播和审计**。实现方式是工程属性，不是证据属性：

- 代码跑通 ≠ 理论成立
- 书稿成文 ≠ 结论可信
- 图谱美观 ≠ 关系真实
- 认证横幅 ≠ 通过审查

## 实现形态分类

| 代号 | 形态 | 典型手段 | 能证明什么 | 不能证明什么 |
|---|---|---|---|---|
| **M1** | 符号推导 | sympy 求导、第一性推导链 | 推导链内部无代数错误 | 前提为真、近似合法 |
| **M2** | 数值精算 | mpmath 高精度、numpy 大规模 | 给定公式的数值行为 | 公式正确 |
| **M3** | 谱方法与打靶 | Leaver 连分数、RK4 双向积分、Richardson 外推 | 特定边值问题的谱 | 物理势来自该理论 |
| **M4** | 格点/离散 | 格点规范、盒计数、元胞自动 | 离散模型的性质 | 连续极限存在 |
| **M5** | 代码库 | 可分发的 Python 包与 CLI | 接口自洽、可复算 | 物理内容正确 |
| **M6** | 书稿与论文 | md/tex/pdf 长文 | 论证可审阅 | 论证正确 |
| **M7** | 可视化 | 单页 HTML、SVG、图数据库 | 结构可读 | 结构为真 |
| **M8** | 治理与审计 | 自洽引擎、量纲审计、勘误台账 | 内部一致性缺陷定位 | 理论成立 |

## 三条使用纪律

1. **实现登记不提升证据等级**。见八层 [T3](../统一架构/统一架构总纲.md)。
2. **认证横幅不算审查**。凡自印"认证通过""OMEGA-PRIME"等横幅而无可复跑脚本与失败明细的，一律按 `conjecture` 登记。
3. **被证伪的实现保留原样**。已判定 FAIL 的方法（如某些打靶脚本）保留在归档中，禁止因结果不利而删除或改定义规避。
