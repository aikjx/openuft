## 57.1 从"硬编码的 0"到真读数

第 55 章记录了 UFT-3 判据依据的一处缺陷。本章记录它的修复过程——因为**修复过程本身比修复结果更有教益**。

### 57.1.1 缺陷的发现

`无量纲靶场审计.py` 中有这样一行：

```python
"n_registered_predictions": 0,   # 需体系自行登记，扫描无法判定
```

它的注释是诚实的（"需体系自行登记"），但它的**后果**不诚实：无论体系实际登记了多少，下游读到的永远是 0。于是"18 体系登记的无量纲预测数 = 0"这条结论**永远成立**。

> **它不是审计结果，它是一个不可被推翻的常量。**

这类缺陷的可怕之处在于：它**不会报错**。脚本照常运行，报告照常生成，数字照常打印——只是那个数字与世界的实际状态无关。本书在第 27 章曾批评某些体系"看起来在验证、实则判不了"，而这次同样的事发生在**审计工具自己身上**。

### 57.1.2 修复

`预测登记与V3判别引擎.py` 改为**直接读取 `claims.csv` 的 `prediction_value` / `prediction_urel` 两列**取真读数；在 `claims.csv` 尚未全量升级时，回落到登记源 JSON，**并在产物中明示读数模式**。

当前真读数：

| 读数项 | 数值 |
|---|---|
| `claims.csv` 中含数值或误差的行数 | **0** |
| 登记源 JSON 中的条目数 | **43** |
| 读数模式 | 登记源 JSON（`claims.csv` 尚未全量升级） |

**必须说清这两者的区别**：

- "等于 0"——这是一个**判决**，暗示"这些体系没有预测"。
- "此刻为 0"——这是一个**读数**，意思是"它们还没把预测写进那两列"。

本书选择后者。前者会把一个**登记习惯问题**误述为一个**科学内容问题**。

## 57.2 登记规范（claims.csv schema v2）

为使"登记"这件事可机器处理，规范强制六列：

| 列名 | 含义 | 强制性 |
|---|---|---|
| `prediction_target` | 靶的键名（`alpha` / `m_mu_over_me` / `n_gen` …） | 必填 |
| `prediction_value` | 预测的数值 | 必填 |
| `prediction_urel` | 声称的相对误差 | 必填 |
| `n_free` | 为得到该值引入的自由参数数 | 必填 |
| `n_anchor` | 为得到该值使用的测量锚数 | 必填 |
| `hit_rule` | 命中判据（$3\sigma$ / 精确相等） | 必填 |

### 57.2.1 为什么这六列都是强制的

少任何一列，判别就会退化为印象：

- 无 `prediction_value` → 无法检验，只能听信。
- 无 `prediction_urel` → 无法判断是否命中（1.4 与 1.41 差多少才算对？）。
- 无 `n_free` → 无法区分"解释"与"拟合"（用 20 个参数拟合 20 个数不算成就）。
- 无 `n_anchor` → 无法识别 M02 型依赖（借用了实验值还宣称导出）。
- 无 `hit_rule` → 事后可以随意选择宽严。

### 57.2.2 一个仓库惯例约束（工程细节，但会咬人）

本仓库 `claims.csv` 的历史惯例是「行末两列定位 `status`」，维护脚本用 `line[-2]` 取值。因此**新列不能追加到行尾**，否则 `status` 定位失效，全库 `verify.py` 会崩。

新列必须插在数据列末尾、`status` 之前。这个约束不优雅，但它是一个真实的、踩过的坑，值得记录以免后人重踩。

## 57.3 采集方法（本节说明数据是怎么来的）

43 条登记**不是**由体系自己填写的——没有体系填过。它们是从各体系的 Markdown 原文中**取证式摘录**出来的。

### 57.3.1 两步法

**第一步：数字特征串检索。** 对 18 个体系全文按下列特征串扫描：

`137.036` · `206.7` · `3477` · `1836.15` · `0.1179` · `0.2312` · `6π⁵` · `e-45` · `ppm` · `1/137` · `0.225` · `8.54` · `1776.86`

**第二步：回读原文上下文，区分两种身份。** 这是全部工作的核心：

| 身份 | 判据 | 处理 |
|---|---|---|
| **体系声称自己算出** | 原文表述为"导出/得到/预言" | 登记为断言 |
| **引用实验值作为输入锚** | 原文表述为"取/代入/已知" | **不登记** |

**这个区分是本任务的全部难点。** 同一个数字 $137.036$ 出现在同一个文件里，可能是该体系的**产出**，也可能是它的**输入**。只有回读上下文才能分辨。

### 57.3.2 硬性纪律

- **严禁臆造。** 找不到就写"该体系未找到"，宁可少报不可多报。
- **数值与摘录取自原文，未润色。** 原文写"1/137.036"就登记"1/137.036"，不换算成小数。
- **保留不利原文。** 若原文自承"这是恒等式"，照实登记，不替它辩护也不替它否定。

### 57.3.3 M02 型条目的特别处理

形如 $m=\hbar\sqrt{\kappa^2+\tau^2}/c$、$G=c^3/(\hbar(\kappa^2+\tau^2))$、$\alpha_{\rm grav}=Gm^2/(\hbar c)$ 这类式子是**恒等式/单位换算**，但它们**仍然是断言**——只是它们落入第 56 章的定理 C 情形 1，会在判别阶段被自动剔除，而不是在登记阶段被人为过滤掉。

**这个顺序很重要**：先如实登记，再由判别规则剔除。若在登记阶段就过滤，就没人能复核"剔除了什么"。

## 57.5 双口径：`formula_origin` 四类来源

登记表里混着性质完全不同的四类东西。若不加区分地计分，会把**已知的数值巧合计成某个体系的产出**。

| 来源 | 条数 | 说明 | 举例 |
|---|---|---|---|
| `system_postulate` **体系自身公设导出** | **22** | 评价**体系**时只计这一类 | S03 的代结构、S10 的频率关系 |
| `known_literature` **既有文献关系移植** | **9** | 从文献搬来的已知数值关系 | Wyler $\alpha$、Koide $K$、Barut $m_\mu/m_e$、GST 关系 |
| `numerology` **小整数 / $\pi/n$ 搜索式** | **10** | 在候选集里搜索得到的近似 | $\lambda\approx\pi/14$、$\theta_{13}\approx\pi/21$、$3/13$、$6\pi^5$、$\alpha^{-3}$ |
| `imported_constant` **外部模型输出** | **2** | 不可观测的模型内部量 | $\alpha_{\rm GUT}^{-1}$ |

### 57.5.1 为什么必须分口径

考虑一个具体情形：

> 某体系在自己的文档里写下 $K=\frac{m_e+m_\mu+m_\tau}{(\sqrt{m_e}+\sqrt{m_\mu}+\sqrt{m_\tau})^2}=\frac{2}{3}$。

这是 Koide 关系，1982 年由 Yoshio Koide 发现。该体系**没有推导它**，只是把它写了进来。若不加区分地计分，这个体系就获得了一次"命中"——而这次命中**属于 Koide，不属于该体系**。

> **把移植算成本体系的产出，是用机器重演了一遍「伪派生」，只是发生在元层面。**

这是本书在元层面上重复了它在对象层面上批评的错误。发现并修正它，是本轮工作最重要的自查。

### 57.5.2 两个口径的定义

- **全口径**（上界）：四类来源全部计入。它回答"这个体系文档里有多少条说得通的数值关系"。
- **仅自身公设口径**：只计 `system_postulate`。它回答"这个体系**自己的公设**产出了多少说得通的数值关系"。

**评价体系本身用后者。** 前者只作为上界参考——它的价值在于显示"剔除了多少"。

### 57.5.3 `formula_origin` 是人工推定

必须明确标注：22/9/10/2 这个分布**不是机器判定的**，是按 `登记源_标注公式来源.py` 中的映射表人工推定的。

若对某条归类有异议，**改映射表重跑即可，不必改引擎**。这是一条刻意的设计：把可争议的判断隔离在一个纯数据文件里，使争议可以被精确指出和快速修正，而不是埋在代码逻辑中。

有些条目不参与命中竞争，但它们**必须被计数并公开**，否则"43 条"这个数字无法与下游的"26 条受评"对账。

**对账**：$43 - 17\ (\text{排除}) = 26\ (\text{受评})$。

### 57.6.1 `calibrated_tautology`：最微妙的一桶

这 5 条的命中残差在 $10^{-16}\sim10^{-12}$ 量级，而 $\alpha$ 的现代观测不确定度是 $1.5\times10^{-10}$。

> **残差比测量精度还小，唯一解释就是：参数由该靶反定标。**

一个真正的预测，其残差不可能**小于**实验误差——除非你先把答案抄进去了。这 5 条因此被排除在"组内最优竞争"之外：否则它们以 $\mathrm{dev}=0$ 会**碾掉**同组里诚实的尝试（如 Wyler 型公式），把后者挤成"未命中"。

**这是一个必须靠规则而非直觉挡住的陷阱**：单看数字，这 5 条是全表最漂亮的命中。

3. **$\mathrm{hit\_rule}$ 的默认值未统一**：整数靶要求精确相等，连续靶用 $3\sigma$。但"多少个有效数字算相等"未定义，某些条目的判定因此有任意性。
4. **`formula_origin` 的归类需要二次复核**：22/9/10/2 由一人推定，未经独立复核。**这个数字应当被质疑。**
5. **靶场未覆盖中微子质量平方差、CKM 全参数、宇宙学参数**：现有 14 个靶偏向"能被体系凑出来的那些"，存在选择效应。

### 核心结论

- **"18 体系预测数 = 0"曾是一个不可被推翻的常量，现已改为真读数。**
- 43 条登记、26 条受评、17 条排除，来自 10 个体系，8 个体系零登记。
- **登记数量不是成就**：S10 独占 16 条，却也是唯一在严格口径下从 A 落 NA 的体系。
- **必须分口径**：22 条自身公设 / 9 条文献移植 / 10 条 numerology / 2 条外部模型。不分口径会把已知数值巧合计成体系产出。
- **`n_free` / `n_anchor` 全部是估算**，这是本册最弱的一环。

## 57.11 本章小结

本章把散落在十八个体系文档里的数值断言，变成了一张可对账、可复核的表。

但这只是登记。有了表之后，真正的问题是：**这些数字里有几个在现代观测精度下站得住？** 下一章用 $V_3$ 判别式逐条检验，并给出本书最不舒服的一个结论——全库唯一拿到 A 档的体系，在更严格的口径下落到了 NA。
