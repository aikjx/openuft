## 五之二 本卷自抓的仪器缺陷（12 枚，全部就地修，不掩盖）

- V2/V8/C5 的**导数阶错位**：链式法则里把 β″ 当 β′、把 β‴ 当 β″（`diff(bg,U)/d1` 是一阶导的再导）。三枚同红不是三个 bug 而是一个 ⇒ 先用只读探针把恒等式在盘外算清（`scratch/r320_fix_probe.py`），再动刀；改后 C5 的「四个不同 β″」才真的成立（β‴ 在 S=0 恒 0，`all(x != 0)` 当场假红）。
- V13 的**跨卷互校对自己要测的结果是盲的**：正则 `1\.92353209028294[0-9]*` 漏掉指数字段 `E-2`，把并发卷印的 0.0192353… 读成 1.92353… ⇒ 判 `r321_agrees=False` 却仍在句尾印「两卷独立算得同值」。修法：正则补 `(?:[eE][-+]?\d+)?`；且 `sp.asinh(sp.Rational(1,2)) - sp.log(phi)` 需 `.rewrite(sp.log)` 才符号归零。★并加一条纪律：**结论从句由布尔驱动**（`if xchk`），不许无条件叙述。
- **递归自哈希导致永不收敛**：报告面里哈希报告面 ⇒ 每次跑消费上一轮的哈希，二跑 md5 必不同。修法：三趟写盘（数据/判定 → 报告最后）+ 报告与 G15 名册跳过 `prods[2]`，并明写「自指不可判」。另一个非幂等源是 `耗时 %s s`——运行量只许进 stdout，不上面。
- V16 **题面硬编码计数与分桶矛盾**：打印「有载体 6 / 部分 2 / 无 1 / 自认红 1」并列和 = 10，而本卷分桶实测 `5/2/1/1` = 9（G12 断言的正是 9）。一句里并列多个同单位计数时，**失效的是标签不是数字**。修法：题面由 `AUDIT_ROWS` 现推；G12 加「题面四个计数 == 分桶四个计数」的针；端到端变异体（把题面改回硬编码 6）实测 **rc=2 且 G12 FAIL**，删变异体重跑干净引擎后 **6/6 面逐字节还原**。
- V11 **把跨卷一致当成自己 PASS 的前提**：他卷同表判 FAIL 的根因是容差口径（比印刷字段半 ulp 更紧），与本卷 12/12 命中无关 ⇒ 解耦：本条 PASS 只由本卷命中数决定，一致性另走 `agree_txt` 且带「未取到」分支。
- 可视化面 `html_text` 尾部留了 `% {}` 而 CSS 里有裸 `%` ⇒ `ValueError: unsupported format character '}'`；占位符本由 `fill_html` 的 `.replace` 填充，格式化那一步是多余的。
- ASCII runner 的 docstring 里写了字面 `D:\a10\...` ⇒ `(unicode error) 'unicodeescape' codec`；runner 一律 glob 本卷引擎名（恰好 1 命中）并从 `__file__` 现推目录，不写任何 CJK 或反斜杠字面量。
- **跨卷尺寸钉「不可复跑」**：收口复核之间观察到本卷数据面的 md5 在一次重跑后自行变动（同一引擎源码、同一批输入），根因是被引的并发卷面（r317/r321/r308）在本卷写盘之后仍在被他卷作者改写，而本卷把它们的「字节 / md5」当可引数值钉进了 V11/V13/V19。写盘那一刻**没有任何仪器能证明他卷会停笔** ⇒ 修法不是「等它落地再钉」（下一轮照样会漂），而是 `stat_of(live=True)` 给每一枚他卷钉逐字打上限定语「只作当下观察，不可后引」，并让收口面新增 W14 做**全量钉普查**：盘上已无此面的钉若不带该限定词即判死账（M22 剥限定词、M23 钉一张不存在的他卷面，各配一枚红）。
- **本卷自己也钉过自己的中间态**：守卫 G15 印的是第一趟落盘时自己各面的 md5，而第二/三趟还在继续重写那些面 ⇒ 同一型死账，只不过对象是本卷。收口 W14 的普查实测「盘上已无此面」的本卷旧钉 3 枚。修法：G15 的名册同样带限定词（标签「本卷自身在后续趟里继续重写该面」），尺寸通道保留（证明面确实落过盘），但明确它不是可后引的终值。
- **登记块是第二个手打源 ⇒ 它与面脱钩**：`_reg_r320.py` 把「本卷自抓 7 枚仪器坑」当字面量写进 README，而面已长到 9 枚；随后用一次性补丁追加 ⑧⑨ 时又打错 3 处 `趟`→`趛`，并把 G15 的标签手打成了与面不一致的字样。⇒ 同一条「硬编码期望值」的病换了个载体再犯一次：登记驱动与 README 之间没有第二个仪器时，错的那个一定是文字。修法：自抓枚数与逐条正文**一律由判定册 §五之二 现推**，登记驱动、同步驱动、收口复核三处共用同一把尺（`_r320_selfbugs.BLOCK_RE`）；W11 钉「登记锚枚数 == 面现数」（M24 把枚数退回面数-3），W17 钉「README 块逐字 == 面现推的那一行」（M25 手打一个缩进续行：枚数不动 ⇒ W11 仍绿，只有 W17 红）；锚只取标题与块首两处，块内 ⑩ 引用的旧字面量「自抓 7 枚」豁免——全局匹配会把缺陷自己的引文判成缺陷（本轮实测：W11 一度因此假红）。README 的自抓块由同步驱动整段重建，改前图像留档 `scratch/_bak_README_pre_r320sync_2026-11-01.md`。
- 同步驱动写盘后又跑第二趟才算数：本轮先只跑了 `--check`（rc=5 表示「有差异待写」，不是失败），真正落盘要第二趟 + 幂等第二跑逐字节相同；`HEAD_RE.sub` 不加 `count=1` 会把块内那句引文一起改掉（实测写盘图像与面派生行在第 1881 字符分叉）。
- **组合器把断句权漏掉 ⇒ 面正文每条自带句号，拼成一行就叠句**：⑩ 之后 README 的自抓块唯一由 `_r320_selfbugs.compose_readme_line` 现推，但那把尺只做「拼接 + 末尾补一个句号」，而 §五之二 的每条正文按列表写法各自以 `。` 收尾 ⇒ 拼出来是 `…。；②` 共 11 处、末条再叠成 `。。`。实测：块 5,331 B → 5,298 B（差的 33 B 恰 = 11 枚 × 3 B，就是被剥掉的 11 个 `。`），README 2,761,307 B → 2,761,274 B。⇒ 这一型 **W17 抓不到**：盘与面同出一把尺，等式两边一起叠句 ⇒ 逐字等式照绿——「切掉第二个手打源」不等于「剩下那把尺是对的」。修法：断句归组合器（每条 `rstrip("。")` 后用 `；` 连接、整行以 `。` 收尾），正文仍只取面上的字面内容；W17 加第二枚**形状针**「块内无叠句」，配 M26 双面变异体（尺子退回不剥句号 **且** README 块同时换成退回后的派生行 ⇒ 枚数与逐字等式全绿，只有形状针红）。**形状针首版本身是假阳**：它按裸子串数 `。；`/`。。`，把本枚 ⑫ 自己引用的那两个形状判成叠句（4 处命中，逐条都在行内代码段里）⇒ 与 ⑩ 里「自抓 7 枚」引文被 W11 判成假红是同一枚坑，本轮换了判据第二次踩。修法同族：计数前先豁免行内代码段（`SB.shape_glue`），并把**豁免段数与豁免后字符数一起印出**——「滤掉了」这件事必须有读数。两口径的对账读数印在 `scratch/_r320_glue_exempt_probe_out.txt`（该探针自报所测的 README 图像），假红原件留在 `判定/收口复核_TUFT-r320_只读复核v5_stdout_2026-11-01.txt` 不覆盖；块自身的尺寸不写进正文：改这段正文就会让它自己失真，形状针在判据里现印现用。改前图像留档 `scratch/_bak_README_pre_r320sync_6aaf060f.md`。
